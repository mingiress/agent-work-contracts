# Project Current-State Checklist

Use only with the project's approved existing current-state authority and storage. This checklist is a template, not a required filename, new authority, or permission to write. Confirm approval and access boundaries before an update. Leave unsupported details unknown; do not include secrets or sensitive contents.

- **Startup route:** Existing instructions followed and how they led to the authority:
- **Current-state authority:** Existing source/link:
- **Objective and phase:** Intended active work:
- **Exact revision and relevant artifacts:** Preserve identifiers literally; note unavailable values:
- **Status:** Declared status, what was directly verified, verification evidence, and unknowns:
- **Blockers and decision ceiling:** What prevents progress; what the recipient may decide or do:
- **Owner:** Responsible person or role, or unknown:
- **One next authorized action:** Include the expected evidence and stop condition:
- **Source links:** Instructions, authority, revision/artifacts, and relevant history:
- **Cold-start drill:** Fresh read-only recipient had only the repository root; outcome (passed / partial / blocked), evidence cited, and unresolved gaps:
- **Portability:** Claim only if approved shared/versioned state was available to the intended recipient and the drill succeeded there; otherwise state “not established.”

If live evidence conflicts with the authority, keep both sources visible, mark status partial or blocked, and request authorized reconciliation. Do not overwrite protected instructions, configuration, ignore rules, permissions, or the existing authority without applicable approval. A checked-in or ignored machine-local file by itself does not establish cross-machine recovery.
